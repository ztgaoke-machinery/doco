# 验收单 · 模块 4：DPR 高清画布（源码包对齐成品）

## 改了哪些文件
| 文件 | 改动 |
|---|---|
| `game/core/state.js` | 新增 `view = { sx, sy, dprOff }`，随 `G.core` 一起导出 |
| `game/core/canvas.js` | `fit()` 重写：按 CSS 尺寸 × devicePixelRatio（上限 2）开后备缓冲，反推 `sx/sy`，发布 `window.__DKDbb_VIEW__`；支持 `?dpr=off` |
| `game/game.js` | `draw()` 首行 `ctx.setTransform(sx,0,0,sy,0,0)`，业务代码继续按 960×560 逻辑坐标写 |
| `game/engine/mouse.js` | `toCanvas()` 改用 `__DKDbb_VIEW__` 的逻辑尺寸（原来读 `cvs.width/height`，放大后点击会偏） |
| `game/boot.js` | `#btn-dpr` 按钮接线：切换 `view.dprOff` → `fit()` → 按钮文字「高清 开/关」 |
| `game.html` | 工具栏新增 `#btn-dpr` 按钮 |
| `_tools/game-harness.mjs` | 测试台 FakeCanvas 忽略 `width/height` 写入（与成品一致，保证断言按 960×560） |

## 游戏里的体现
- 高分屏（笔记本 125%/150% 缩放）和把窗口拉大时，标题文字、UI 边线、地图像素不再发糊。
- 右上角工具栏多一个「高清 开」按钮，点一下变「高清 关」＝回到旧的 960×560 行为，可直接对比。
- URL 加 `?dpr=off` 可永久关掉（本次刷新内）。

## 测试结果
- `node _tools/run-all-tests.mjs`：**56 个文件 / 51 通过 / 5 失败**，断言 **2191 通过 / 17 失败**。
  与改动前基线**完全一致**；5 个失败正是方案文档 §6.5 的免检清单（dungeon / scene-d4 / scene-names / conversation-export / handoff-bundle）。

## 实测证据（浏览器，localhost:8791）
| 场景 | CSS 尺寸 | 后备缓冲 | sx | 鼠标映射 |
|---|---|---|---|---|
| 默认小窗（dpr=1，CSS 807px < 960） | 807×471 | 960×560 | 1 | 239.7 / 419.7（期望 240 / 420）✅ |
| 模拟大窗 1440px、dpr=1 | 1400×817 | **1400×817** | 1.458 | ✅ |

| 同大窗、点「高清 关」 | 1400×817 | 960×560 | 1 | 旧行为，放大后发糊 |

## 最短人工验证路径
双击 `2-源码-可重建/game.html` → 把浏览器窗口最大化 → 点右上角「高清 关」→ 标题文字立刻变糊；再点回「高清 开」变清晰；期间用鼠标点菜单项，确认点击位置与光标一致（不偏移）。

## 与成品的已知差异（需你拍板）
差异清单里模块 4 提到「开关状态持久化」，但**成品并没有做持久化**（只有 `?dpr=off`）。本模块按「源码 == 成品」的验收标准保持 1:1，未额外加持久化。若确实要持久化（存进 `save.data`），说一声我加，约 5 行。
